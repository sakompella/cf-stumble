## Acceptance criteria

### 1. Instructions reach the prompt, and only the selected project's

Holds. `src/facet/generation-0/instructions.ts` reads the managed file at
`MANAGED_AGENT_INSTRUCTIONS_PATH` (T3a's exported constant in `src/workspace-layout.ts`, value
`/workspace/AGENTS.md`) and the repository file `AGENTS.md` relative to the turn's working
directory. Both reads go through `ExecutionEnv.readTextFile` on the adapter the tools use, so they
cross the same project RPC target.

`test/facet/generation-0/instructions.test.ts` builds one shared workspace holding two project
clones over a single real `ProjectRpcTarget`, and proves:

- the managed text and `project-one`'s own text both appear in the system prompt the route received;
- `project-two`'s text does not, although both clones live in the same workspace;
- a turn started for the second project sends the second project's messages only — the first
  project's conversation is not in the request, because a conversation is an argument of a turn and
  the workspace is the only thing the two projects share;
- an unprovisioned workspace and a project with no `AGENTS.md` both run rather than failing.

`runPiAgentTurn` rebuilds the prompt from `GENERATION_0_SYSTEM_PROMPT` on every turn rather than
continuing the saved one, so it does not accumulate a copy of the instructions per turn and a
re-provisioned workspace changes a conversation already in progress.

### 2. Compaction uses Pi's behaviour, before the budget is exceeded

Holds, with one honest substitution recorded below.

**What Pi does with a zero context window — settled before claiming this.**
`vendor/pi-v0.84.4/packages/agent/src/harness/compaction/compaction.ts:247-250` is
`if (!settings.enabled) return false; return contextTokens > contextWindow - settings.reserveTokens;`
There is no division and no fallback. With `ROUTE_MODEL.contextWindow === 0` and the default
`reserveTokens: 16384`, the threshold is `-16384`, so an *empty* conversation exceeds it. A zero
window does not make the trigger unreachable, as E7 suspected; it makes it always true, which would
compact on every turn. `test/vendor/pi.test.ts` and `test/facet/generation-0/compaction.test.ts`
both assert `shouldCompact(0, 0, DEFAULT_COMPACTION_SETTINGS) === true`.

**Where a real number could honestly come from.** `src/model-route.ts:16` pins
`MODEL = "@cf/zai-org/glm-5.3-flash"`. The context window of that model is a published fact of the
model the route selected, so the route — which owns the model id, the endpoint, and the credential —
is the only component that can state it without inventing it. T7 did not add it there:
`src/model-route.ts` and `route-stream.ts` belong to T4, and `ROUTE_MODEL`'s own comment says this
generation "has no way to learn the real values and must not invent them". Publishing the pinned
model's documented window through `ModelCapability` is a small follow-up for whoever owns the route.

**What T7 did instead.** `GENERATION_0_COMPACTION` in `turn-policy.ts` declares a budget of 64,000
context tokens with `keepRecentTokens` lowered to 8,000, and `needsCompaction` passes that budget to
Pi's own `shouldCompact`. The decision rule stays Pi's; only the number is this generation's, stated
the same way `MAX_MODEL_CALLS` is stated — a bound the harness chooses, not a measurement it claims.
`keepRecentTokens` must stay below `budget - reserveTokens` or compaction would retain everything it
was asked to summarize; the test asserts the budget-versus-reserve relation.

**The forced-compaction proof.** `test/facet/generation-0/compaction.test.ts` runs a turn with a
one-token budget and zero reserve, over a four-message conversation:

- the first request the route sees carries Pi's own summarization system prompt, so the summary is
  Pi's and no second summarizer was written;
- the saved state begins with a `compactionSummary` message carrying the summary text;
- the turn itself ran on the compacted context;
- a **replacement facet** — a new execution environment over the same workspace and a new route,
  handed nothing but the saved state — sends the summary to the model, so the compacted context
  survived facet replacement;
- starting fresh (`createPiAgentTurnState`) has no messages, while a file written before compaction
  is still readable through the same workspace;
- a route that cannot summarize leaves the conversation intact rather than losing it.

Compaction runs before the turn's first model call, not between calls. Pi's `transformContext` hook
changes only the request and hands the untransformed messages back
(`vendor/pi-v0.84.4/packages/agent/src/agent-loop.ts:286-290`), so a compaction placed there would
be paid for again on every later turn and never saved.

`MODEL_CALL_LIMIT_NOTE` was deleted rather than moved: nothing consumed it once the buffered turn
went, and the `failed` frame already reports `model-call-limit` as a code.

### 4. The Pi path produces a repository diff

Holds, by `bash` plus `git diff` rather than by keeping a diff tool.

Pi's `bash` tool has no command allowlist, the project clone is an ordinary checkout
(`projectGitDirectory` is `<project>/.git`), and `execution-env-exec.ts` passes the command straight
to the project target. `test/facet/generation-0/turn-diff.test.ts` drives a turn whose model calls
`bash` with `git diff`, answers the command through the real project RPC target's exec backend, and
reads the frames.

**The stated budget.** A tool-result frame is bounded at 2,000 lines or 51,200 bytes
(`TOOL_RESULT_DISPLAY_MAX_LINES` / `TOOL_RESULT_DISPLAY_MAX_BYTES` in `turn-policy.ts`), applied with
Pi's `truncateTail`. Those are the same two limits Pi's own `createBashTool` and `createReadTool`
apply to their output, so a frame never truncates a result Pi already bounded.

The test proves a forty-line diff (about 1.6 KB, a tenth of the budget) arrives whole with
`truncated: false`; a 1,800-line diff just under the budget also arrives whole; a 4,000-line diff
over the budget is cut, marked `truncated: true`, bounded at 51,200 bytes, and keeps the *end* of the
diff, which is what a reader needs. A failed `git diff` becomes a tool-error frame carrying what the
command printed.

`git_diff` and the `git-diff` workspace operation were therefore deleted in this same commit, as the
task requires: the replacement landed with them.

### 5. Typed plain frames, and exactly one terminal outcome

Holds. `FacetTurnFrame` (`turn-frames.ts`) is `text`, `tool-start`, `tool-result`, `completed`,
`failed`, `rejected`.

- **Incremental text.** One frame per `text_delta` the route produced.
  `test/facet/generation-0/turn-frames.test.ts` drives a route that emits three NDJSON text deltas
  and gets three text frames. A route that answers whole still publishes its reply exactly once:
  `TurnFrames` remembers how much it has already published and emits only the remainder at
  `message_end`.
- **Tool start with arguments.** `{ kind: "tool-start", toolCallId, toolName, arguments }` from Pi's
  `tool_execution_start`.
- **Tool results with bounded displayable content.** `content` and `truncated`, budget as above.
- **Exactly one terminal frame,** and the three are different facts: `rejected` means no turn ran and
  carries no state; `failed` carries the conversation a model error or the call limit still produced;
  `completed` carries the state the next turn continues from. The test counts terminal frames and
  checks that both `completed` and `failed` carry messages while `rejected` is alone in its stream.

This facet terminal outcome stays provisional until T9 saves it (ADR-0037). Nothing here claims a
completed real turn.

### 6. Cancellation, and unsupported `ExecutionEnv` methods

Holds. Cancellation is unchanged and still covered: `facet-turn.ts` aborts the run and releases the
lease on cancel, and `test/facet/generation-0/facet-turn-disposal.test.ts` and
`facet-turn-loaded.test.ts` still pass.

No previously unsupported `ExecutionEnv` method was required. Instruction loading needs
`absolutePath` and `readTextFile`, both already implemented, and
`test/facet/generation-0/instructions.test.ts` exercises them through the real `ProjectRpcTarget`
rather than through a stub environment. Compaction needs no `ExecutionEnv` method at all — the
compaction module never touches the filesystem. No tool was added.

The one interface that had to be widened is Pi's `Models`, not `ExecutionEnv`. `route-models.ts`
implements `completeSimple` — the only member Pi's compaction uses — against the host route, and
reports every provider, model-catalogue, authentication, login, and deferred member as unavailable,
because this generation has no provider registry and no credential to build one from. `complete` and
`stream` are reported unavailable too: they carry options a specific provider's API defines, which
one fixed route cannot honour. That is the same shape `createFacetExecutionEnv` already takes with
`ExecutionEnv`.
