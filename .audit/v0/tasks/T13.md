## Acceptance criteria and their evidence

**1. A turn that modified the workspace can show what changed without the model's cooperation.**
`facet-turn.ts:pumpTurn` runs `readWorkspaceDiff` whenever the turn published a `tool-start` for
`bash`, `edit`, or `write`, whatever the model said. Evidence:
`test/facet/generation-0/turn-diff.test.ts`, "a turn that edits a file shows the diff even though
the model never asks for one" — the scripted model calls `edit` and then speaks; the test asserts
no `bash` tool-start exists in the stream and that the `diff` frame carries `-  return 41;` and
`+  return 42;`. The same property across three isolates:
`test/supervisor/projects/project-turn.test.ts`, "a turn shows what it changed without the model
asking for a diff" — the turn writes `notes.txt` over a real RPC hop and the diff comes back
containing `+written by the turn`.

**2. The test proves the property, not the frame budget.** Nothing in the new tests supplies the
diff text it asserts. `GitDiffExecBackend` reads the provider's real bytes at diff time and
computes the hunk. Two checks make that hard to fake past:
"a command that changes nothing produces an empty diff" (the frame's content is `""`, so the
backend cannot be printing a canned string), and the assertion in test 1 that the file on disk
really contains `return 42;`. The byte-budget test drives a command that rewrites 4,000 real lines
and asserts the frame is bounded and marked `truncated`. Renaming the command would break every one
of these tests, because the backend answers exactly `TURN_DIFF_COMMAND` and nothing else.

**3. A diff that cannot be produced says so.** "a workspace that cannot answer says so instead of
pretending the turn changed nothing" — the command exits 128 with git's own wording and the turn
publishes `{ kind: "diff-unavailable", detail: "fatal: not a git repository ..." }` before its
terminal frame.

**4. A turn that changed nothing publishes no diff.** "a turn that only reads publishes no diff at
all" — frames are exactly `tool-start`, `tool-result`, `text`, `completed`.

**5. The frame is bounded and honest about truncation.** The exec path already truncates a
command's buffered output silently to the same limits, so `readWorkspaceDiff` counts the bytes the
command printed through `onStdout` and marks the frame truncated when more was printed than
survived. Asserted in the budget test (`truncated === true`, content ≤ 51,200 bytes, ≤ 2,000 lines,
and the end of the diff is what is kept).

**6. Exactly one terminal frame still ends a stream, and the Supervisor's rules are unchanged.**
The diff is published before the terminal frame, never instead of it. `turn-credit-flow.test.ts`
and `turn-faults.test.ts` still pass unchanged apart from the two added tests; credit still needs
terminal success plus a committed save.

**7. `pnpm verify` passes.** Run before the commit and again by `.githooks/pre-commit`
("pre-commit: verifying... ok"). 116 files / 834 tests, about 16 s on this machine.

**8. Clean-build probe re-run.** `scripts/probe/clean-build.sh HEAD` at `ad35ccf7`: build 1 and
build 2 both 942,366 bytes, sha256 `e9c3008e...` for both, "Two clean builds ... produced identical
module maps". As review 2.2 says, this is a regression guard against E1, not evidence for goal

## What is still model-dependent, and what is not proved

- **Whether a turn changes anything at all.** The model still decides to edit. The harness only
  guarantees that *if* a turn used a tool that can change a file, the turn ends with the
  repository's answer about what changed. Nothing here makes a lazy turn do work.
- **The reply text.** The model still writes the sentence that tells the user what it did
  (criterion 4's "reports"). The diff, the tool activity, and the command output no longer depend
  on it.
- **A file created and never staged is not in `git diff HEAD`.** A turn that writes a brand-new
  file into a real repository will show it only after something adds it to the index. Covering
  untracked files needs a second command and a second frame; that was outside the cut line, and
  criterion 4's demo turn edits an existing file. This is a harness limit, not model dependence.
- **`git` in a real workspace is unverified.** No test in this repository runs a child process
  (workerd), so "the command exists, the project directory is a repository, and it prints a diff"
  is proved only against `GitDiffExecBackend`. Proving it for real needs a Computer workspace:
  **blocked: awaiting owner approval for a paid probe.** The failure path is at least explicit —
  a non-zero exit becomes `diff-unavailable` with git's own message rather than a silent empty
  diff.
- **The browser does not render the new frames yet.** `src/page/` has no streaming client at all
  (review 2.3), so T10 must render `diff` and `diff-unavailable`. Both already reach the browser
  as proven fields.

## Unrelated faults noticed, not fixed

1. **Tool results can be silently truncated.** `execution-env-exec.ts` accumulates stdout through
   Pi's `truncateTail` with default limits, so a long command's output is already cut before
   `turn-frames.ts` measures it; a `tool-result` frame can therefore carry `truncated: false` for
   output that was cut. The diff frame works around this by counting printed bytes. The same fix
   belongs on tool results, which is a change to `turn-frames.ts` outside this task's scope.
2. **`turn-credit-flow.test.ts` still scripts `bash {command: "git diff"}`** in its `completedTurn`
   fixture. It is only a payload for the credit rules, but it now reads as if the model were
   expected to run the diff.
3. **`scripts/probe/clean-build.sh` passes `PATH="$PATH"`** so both builds share the host
   toolchain (already recorded as review 2.2).
