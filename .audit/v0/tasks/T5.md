## Design: what fences a turn

A turn is admitted by `ThreadStore.startTurn`, which mints a lease id with `crypto.randomUUID()`,
writes it into the row, and returns it once to the caller it admitted. Finishing or abandoning that
turn requires the same id. The row holds at most one lease id, and every commit, abandonment, and
fresh thread clears it, so an id that still matches proves both that the caller was admitted and
that the thread has not moved on to a replacement. That is why `finishTurn` no longer takes an
expected revision: the revision it was admitted at cannot have changed while its lease still
matches, so restating it would add a second key that proves nothing new.

`revision` is now the thread's monotonic concurrency version rather than a count of committed
turns. It advances on every committed turn and on every fresh thread, and never repeats for a
project. `startFreshThread` therefore updates the row instead of deleting it: deleting restarted
the count at zero, and a caller that had read the replaced conversation could be admitted into its
replacement because its stale number matched again. The statement is one `INSERT ... ON CONFLICT DO
UPDATE` that sets `messages = NULL`, `revision = revision + 1`, and clears the lease, so it never
reads the conversation and still replaces a damaged row.

## Acceptance criteria

**1. Every finish or abandon operation requires the lease ID that admitted that turn; the unkeyed
paths are gone; lease ids stay server-owned.** Holds. `ThreadStore.finishTurn` and
`ThreadStore.abandonTurn` take a required `leaseId: string`; `startTurnWithLease`,
`finishTurnWithLease`, `abandonTurnWithLease`, the optional-`leaseId` `commitTurn` and
`releaseTurn` helpers, and the `ownsLease` probe are deleted. `grep -rn "WithLease" src test` now
matches nothing. The id is minted in the store, returned only by `startProjectTurn`, and never
appears in `SerializedThread`; the two HTTP routes that exist (`GET /api/projects/:id/thread` and
`POST /api/projects/:id/thread/fresh` in `src/routes/owner-api.ts`) return `ProjectThreadResult`,
which has no lease id, so the browser cannot learn or return one. Tests: "a finish presenting a
lease the store never issued is refused" and its abandon twin in `turn-lease.test.ts`; the
`admit` helper in each thread test now has to carry the returned lease id to complete a turn.

**2. A late finish or abandon from turn A cannot alter turn B after expiry/takeover at the same
revision.** Holds, for both operations. `turn-lease.test.ts` admits turn A at revision 0, lets its
deadline pass, and lets turn B take the slot over at the same revision 0. Turn A's finish is
refused with `turn-lease-lost` and turn B then commits its own conversation; turn A's abandon is
refused with `turn-lease-lost`, the thread still shows turn B's deadline, and turn B still
commits. "A lease dies with the turn it admitted and cannot be presented twice" covers replay of a
spent lease, and "a finish holding a completed turn's lease is rejected" covers the same lease
after the thread moved to the next revision.

**3. Fresh thread invalidates old leases even when revision zero recurs.** Holds, and revision zero
cannot recur for a project. The reset race is tested through storage in `fresh-thread.test.ts`: "a
delayed start cannot enter a replaced thread by presenting its old revision" admits a turn on a
thread nobody has committed to (revision 0), starts a fresh thread, and then finds the delayed
start with revision 0 refused as `stale-revision` with `currentRevision: 1`, while the old lease's
finish and abandon are both refused. Before this change the same sequence was accepted: a probe
test at the base commit asserted the delayed start must fail and reported
`expected { ok: true, thread: {...} } to match object { ok: false }`. The probe also showed the
late finish after takeover succeeding. The probe file was deleted once the real tests replaced it.

**4. Starting fresh clears Pi messages and compacted context without touching workspace files, and
cannot let the old lease save into the replacement.** Holds. The existing fake-workspace test still
proves the reset makes no workspace call and leaves the files a turn wrote, and it now also proves
the revision advances (0 -> 1 -> 2 across a committed turn and a reset). The compacted context is
part of the stored conversation, which the reset sets to `NULL`. "The replaced thread's lease
cannot save into the turn that replaced it" admits a turn, starts a fresh thread, admits the
replacement turn, and shows the old lease refused with `turn-lease-lost` while the replacement's
own lease commits. The later coordinator receives its own lease id and the new revision from
`startProjectTurn`, which is the identity it needs to fence its predecessor's work; the displaced
lease id is deliberately not returned, because the fresh-thread result is the one thread value a
browser can already read over HTTP.

**5. Reads, admission, and writes use the existing synchronous transactions and plain serialized Pi
messages; one active turn per project; an expired lease permits a new admission without an alarm.**
Holds. Every store method still runs inside `storage.transactionSync`, the conversation still
crosses as the serialized string the column holds, and no alarm was added. `decideStartTurn` is
unchanged, so a second start during a live lease is still `turn-conflict` and a start after the
deadline still takes the slot over; both cases keep their existing tests in `threads.test.ts`.

## What I deliberately did not do

- No HTTP route for `startProjectTurn`, `finishProjectTurn`, or `abandonProjectTurn`. E6 confirmed
  none exists, and the turn surface is T9's work. The RPC wrappers and their tests are the whole
  migration.
- No change to Supervisor construction, `workspace-names.ts`, or `artifacts/` (T3's scope), and no
  change to `streamProjectTurn` behavior. Only two sentences of its doc comment changed.
- No new ADR. The lease rule refines how ADR-0038's one thread per project admits a turn; it does
  not reverse a recorded decision. ADR-0035 (plain values across the boundary) and ADR-0036 (pure
  decisions, imperative shells) are both preserved: the lease comparison moved out of the shell
  into `decideFinishTurn`/`decideAbandonTurn` as a plain `TurnLeaseClaim` fact.
- No coordinator that joins admission, streaming, and saving. That is the unit the existing
  `streamProjectTurn` comment names, and it belongs to T9.
- No paid probe. Nothing in this task needs one; `pnpm verify` runs locally in workerd.
