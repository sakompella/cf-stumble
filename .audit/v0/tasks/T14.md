## Acceptance criteria and evidence

1. **A turn that edits a file ends with its diff visible in the transcript.**
   `diffMessage` appends one message entry (`messageEntry("diff", "diff")`, matching the pattern
   `toolBlock`/`textMessage` already use) whose body is filled by the existing `renderOutput`
   helper. Because `diff` frame content already looks like a unified diff
   (`diff --git`/`@@`/`+++`/`---`), `renderOutput`'s existing `looksLikeDiff` check is true and the
   content renders through the existing per-line `diffClass` colouring (`.diff-line.added`,
   `.diff-line.removed`, `.diff-line.hunk` in `src/page/styles.ts`, unchanged) — the "diff colours"
   T10 already shipped. Evidence: `test/page/owner-page.test.ts` new test asserts
   `frame.kind === "diff"` and `diffMessage(frame)` are present in the delivered script; the parse
   test (`new Function(script)`) proves the script still parses.

2. **A turn whose repository could not answer shows the reason (`detail`) instead of silence.**
   `diffUnavailableMessage` appends one message entry (`messageEntry("diff unavailable", "diff")`)
   whose body is `frame.detail` set via `textContent` (never markup). Evidence: the same new test
   asserts `frame.kind === "diff-unavailable"`, `diffUnavailableMessage(frame)`, and `frame.detail`
   are present in the delivered script.

3. **A long diff must not break the page; a truncated diff says so rather than pretending to be
   whole.** `diffMessage` checks `frame.truncated` (the field T13 added) and appends a `"note"` span
   reading `"… the harness truncated this diff"`, the same pattern `toolResult` already uses for
   `"… the server truncated this output"`. Evidence: the new test asserts the string
   `"the harness truncated this diff"` is present in the script; `renderOutput`'s own
   `DISPLAY_MAX_CHARACTERS`/`DISPLAY_MAX_LINES` bound (unchanged) still applies, so even an
   over-length diff line count cannot break page layout.

4. **Real field names, no invented shape.** Both handlers read exactly the fields
   `src/facet/generation-0/turn-frames.ts` and `src/supervisor/projects/turn-frames.ts` declare:
   `diff` → `content`, `truncated`; `diff-unavailable` → `detail`. No new field was added to either
   frame type, and neither source file was touched.

5. **Follows T10's rendering shape.** No restyle, no new framework/bundler/router. The two new
   functions are added to the same file (`script-render.ts`) and follow the same helper contract

## What I deliberately did not do

  (`.diff-line`, `.diff-line.added`, `.diff-line.removed`, `.diff-line.hunk`) the brief said to
  check for before adding any; I reused it as-is and added none.
- Did not persist `diff`/`diff-unavailable` into the saved-thread rendering path
  (`src/page/script-conversation.ts`). Those frames are the harness's ephemeral turn-stream

  reconstructs from `thread.conversation`; a page reload or a second browser loading the saved
  thread will not show the diff of a completed turn, only what happened during a still-open
  connection to that turn's stream. Re-deriving or persisting a diff after the fact was out of this
  task's cut line (no change to any frame's shape, no new endpoint, page-side only).
- Did not run `pnpm harness:browser` (the browser harness). `tools/browser-harness/` does not exist
  on this branch/worktree (its introducing commit is `wip(T10): browser harness, phase 2 unfinished,
  never gate-verified`, not present here), so there is no browser harness to run in this
  environment. This is outside `pnpm verify`'s gate per `AGENTS.md` and was not required to prove
  the acceptance criteria above.
- Did not touch `src/facet/**` or `src/supervisor/**`, as the cut line requires.
- Did not restyle, refactor T10's modules, or touch any other frame kind's rendering.
- Noticed but did not fix (out of scope, listed for a future task): none — the change was narrow
