## Acceptance criteria

### 1. Collapsible sidebar of connected projects, and selection drives the conversation

Holds. `src/page/markup-sidebar.ts` renders `<aside id="project-sidebar">` with a
`#project-sidebar-toggle` button carrying `aria-expanded` and `aria-controls`; the toggle adds
`sidebar-collapsed` to `#owner-layout`, which `styles.ts` hides. `script-projects.ts` reads
`GET /api/projects` (T6a's real catalog) and renders one `button.project-button` per connected
project with its display name and repository url, and the GitHub connection state beside it.
Selecting a project sets `page.projectId`, clears the transcript, and loads that project's thread;
every later turn posts to that id. The connection flow is the device flow: the page shows the
verification link and the short user code and has no token field at all (ADR-0039).
Evidence: `test/page/owner-page.test.ts` — "a project is chosen from the tenant's catalog, never
typed in", "the sidebar collapses and the generation controls stay in a drawer"; browser evidence in
the harness run below.

### 2. Render deltas, tool calls, bounded output, diffs and terminal status as they arrive

Holds. `script-turn.ts` posts to `POST /api/projects/{id}/turn` and reads the response body with
`getReader()`, splitting newline-delimited frames as they arrive; it handles every kind in
`ProjectTurnFrame` (`src/supervisor/projects/turn-frames.ts`) and nothing else. Text frames append
text nodes to the current assistant block, `tool-start` opens one collapsed `<details>`, and
`tool-result` fills it, marks failure, and renders a unified diff line by line with adds and removes
coloured. Content is text: the script assigns no HTML anywhere, so repository content and model
output cannot execute. Large output cannot make the page unresponsive: the Supervisor already bounds
a tool result, and the page bounds what it lays out again at 20000 characters / 400 lines and leaves
the block collapsed.
Evidence: `test/page/owner-page.test.ts` — "the streaming client reads the frames the turn route
emits" (every frame kind, `getReader()`, `application/x-ndjson`, `AbortController`) and "the page
never turns repository or model output into markup" (no `innerHTML`/`outerHTML`/
`insertAdjacentHTML`/`document.write`/`eval`).
Deviation: content is rendered as plain text, not sanitized Markdown. The criterion allows either.

### 3. Fresh thread, busy and conflict, disconnected, failed-save, no-active-generation

Holds in the client. `#turn-state` words each state from the server's own answer: `turn-conflict`
becomes "busy: another turn holds this project", `no-active-generation` becomes "no active
generation: activate one in the generation controls", a `save-failed` frame becomes "not saved:
<code>", a fetch failure becomes "disconnected: the turn stream ended early", and an abort becomes
"cancelled". Success is only ever the Supervisor's `saved` frame (ADR-0037), never an HTTP status.
Starting fresh takes two clicks: the first arms and states that repository files are untouched.
A second browser sees the same saved thread because a project selection renders
`thread.conversation` from `GET /api/projects/{id}/thread`, which is the committed conversation.
Switching projects cannot append a late frame: selection bumps `page.selection`, aborts the running
fetch, and every asynchronous renderer drops an answer whose token no longer matches.
Evidence: `test/page/owner-page.test.ts` — "starting a fresh thread takes a second, deliberate
click"; the late-frame guard and the second-browser reload are browser-level and are asserted in the
harness scenario.

### 4. Active label and observed epoch visible, controls in a compact drawer

Holds. `markup-drawer.ts` keeps `#active-generation-label`, `#generation-epoch`,
`#active-generation-status` and the harness commit visible above the conversation, and puts
submission, activation, rollback and the latest recovery report inside `<details
id="generation-drawer">`, closed by default (Q4). Activation and rollback still send the epoch the
page rendered from `GET /api/status` (ADR-0033). The recovery note still says cf-stumble repairs
nothing by itself and that rollback is manual.
Evidence: `test/page/owner-page.test.ts` — "the sidebar collapses and the generation controls stay
in a drawer", "the page states that recovery repairs nothing by itself".

### 5. No free-text project id, no raw JSON, CSP nonce, same-origin, no-store

Holds. The project-id input and the `project-one` default are deleted, as is every `-raw` panel and
the `setRaw` helper. `src/routes/page.ts` is unchanged, so the nonce, `no-store`, and the
`default-src 'none'; connect-src 'self'` policy are the ones that already shipped; the page carries
no inline event attribute, so one nonced script is all the policy has to admit. Every request is a
relative path with `credentials: "same-origin"`.
Evidence: `test/page/owner-page.test.ts` — "the page shows no raw JSON panel", "the page uses only
the owner JSON endpoints, on this origin", "the page asks for no credential and stores none";
`test/routes/page.test.ts` — "the page policy allows only inline code from this response and this
origin".
Deviation, recorded rather than hidden: the criterion also asks for browser logic in checked
TypeScript "rather than expanding opaque script strings". The dispatch brief's cut line for this
task forbids a build step, a bundler, and a framework for the page, and those are the only ways to
ship real TypeScript to a browser here. The page therefore keeps the existing pattern — inline
script text assembled in TypeScript modules, with every element id interpolated from
`element-ids.ts` so markup and script cannot drift. Two checks stand in for the type checker: the
delivered script is parsed as JavaScript in the suite, every id the script reads is proved to exist
in the markup, and the browser harness runs the script for real.

## What this task deliberately did not do

- No framework, bundler, build step, client router, reconnect or resume, and no offline cache. The
  page is still one Worker response with one inline stylesheet and one inline script.
- No change to any backend route, Supervisor method, or frame shape. The client was built against
  `src/routes/turns.ts`, `src/routes/projects.ts` and `src/supervisor/projects/turn-frames.ts` as
  they are.
- No Markdown rendering. Text only, which is the safer half of what criterion 2 allows.
- No cancel path added to the server. The page cancels by aborting the fetch, which cancels the
  response body — the mechanism `turn-stream.ts` documents. There is no `DELETE .../turn` route to
  call, and adding one is backend orchestration this task is not allowed to touch.
- No edits under `test/routes/` other than `page.test.ts`; T11 owns the rest.

## Things noticed and not fixed (out of scope)

- `GET /api/projects/{id}/thread` returns the whole conversation on every read. That is fine at
  version 0 sizes and would need a bounded read before a long thread.
- There is no HTTP surface for cancelling a turn other than dropping the response body, so a browser
  that is closed mid-turn is the only cancel signal the Supervisor gets. ADR-0037 accepts this.
- `src/routes/owner-api.ts` answers `/api/github/authorization` for a body it never reads. Harmless,
  but a reader of the page's `authorizeGitHub` call may expect otherwise.
