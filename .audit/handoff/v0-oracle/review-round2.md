## 2. Claims that do not hold, or hold weaker than stated

### 2.1 T7 / D62 — "the Pi path produces a diff" is proven only as far as the frame

`.audit/v0/tasks/T7.md` and D62 treat B3 as answered because
`test/facet/generation-0/turn-diff.test.ts` drives `bash` with `command: "git diff"` and checks the
tool-result frame. Read what that test actually supplies:

- `test/facet/generation-0/turn-diff.test.ts:41-56` — `diffTurn(stdout)` scripts the model with
  `calls("bash", { command: "git diff" })`, then **hand-feeds the stdout**:
  `handle.push({ name: "stdout", data: new TextEncoder().encode(stdout) })` against
  `FakeProjectCapability`. No git runs. The diff text is generated by `diffText(hunkLines)` at
  line 12.
- `src/facet/generation-0/turn-policy.ts:13` — the only thing that makes a diff happen in
  production is the sentence "Run `git diff` with the bash tool when the user asks what changed"
  inside `GENERATION_0_SYSTEM_PROMPT`.

So three separate things are unproven and each of them breaks criterion 4's demo turn:

- **The model must choose to run it.** Q6 pins `@cf/zai-org/glm-5.3-flash` at
  `reasoning_effort: "low"`. A flash model at low effort skipping one instruction in a five-clause
  system prompt is an ordinary event, not a tail risk. There is no deterministic fallback: nothing
  in the harness appends a diff when the model does not ask for one.
- **`git diff` must work in the workspace.** Unverified — it needs a real container, which is
  blocked on Q7.
- **The test is a good test of the frame budget and a non-test of the feature.** It would still
  pass with `git diff` renamed to `cat`, because the string never reaches a git.

This is not "the worker's alternative was better", which is what D62 concluded. It is "the worker's
alternative proved a different, easier property, and the check was relaxed to match it". D40's
lesson (assert the property, never the shape) was applied correctly to T1a and T5; on T7 it was
applied to the wrong half. The property was "a real turn shows a diff"; what got asserted was "a
frame can carry 50 KB".

**Fix:** either bind a diff capability the harness controls (so the turn always ends with the
repository's real diff, whatever the model does), or make it an explicit criterion-4 release risk
and prove it in the criterion-10 recording with the real model. Do not carry it as closed.

### 2.2 The clean-build probe proves reproducibility on one machine, not two builds

`scripts/probe/clean-build.sh` is honestly written — separate `HOME` per build, separate pnpm
store, `env -i`, and it refuses to run if the extracted tree already contains `node_modules` or
`vendor/pi-v0.84.4/dist` (lines 58-62). It says so itself at lines 12-14: "a fast pre-check for
goal criterion 7, NOT the criterion itself". But `PATH="$PATH"` (line 69) hands both builds the
host's node and pnpm. Two builds on one machine with one toolchain is a weaker statement than
criterion 7's "two clean Computer builds". Treat the probe as a regression guard against E1, not as
evidence for criterion 7.

Also worth carrying forward as a real risk, measured by the probe: **598M cold store, 491M build
directory** per build. That is a container disk-budget question for T1b, not a rounding error.

### 2.3 Criterion 4's UI half does not exist at all

`src/page/` is 645 lines across nine files and contains no sidebar, no collapsible anything, and no
streaming client — `grep -rln "sidebar\|collapsib\|EventSource\|ReadableStream" src/page/`
returns nothing. That is T10's job and T10 is unstarted, so this is not a broken claim; it is a
correction to any reading of "T4 closed the streaming criterion". T4 closed the *server* interface.
