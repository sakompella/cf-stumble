## Known limits and questions

A repeated passing preparation check leaves the generation status unchanged, but records a new
preparation-check history row and advances the control epoch. ADR-0033 requires the epoch to
advance for preparation-check changes, and `test/supervisor/epoch-scope.test.ts` checks this case.
The `effect: "no-op"` result describes the status update, not the whole transaction.

- **Workspace exclusion during a turn is isolate-local, not Durable-Object-scoped.** The guard
  lives in `src/supervisor/supervisor.ts` and `src/workspace/provisioning.ts`, gated at admission.
  It protects one Supervisor isolate; nothing moves this coordination into the `WorkspaceHost`
  Durable Object, which is where a real boundary across isolate evictions would need to live.
- **No ADR records the size-guard thresholds.** The three numbers above are new in `eafaf99` and
  have a stated rationale in a code comment (`project-connections.ts` line 66, "150 MB leaves
  ..."), but `docs/agents/adr/README.md`'s index has no matching entry and
  `docs/agents/adr/0039-treat-the-workspace-as-a-development-machine.md` does not mention
  repository size. Whether three specific numeric ceilings clear the project's own bar for an ADR
  ("expensive to reverse, a real alternative, would surprise a future reader") is a call for the
  project owner, not something a docs pass can settle.
