# Use better-result only inside process boundaries

> **Review:** Agent-only

cf-stumble uses the better-result library to represent failures that one function hands to another inside a single Worker isolate. A function that can fail returns a result value carrying either its success or a tagged error, and the caller must inspect that value before it can reach the success. This replaces hand-written union types whose failure arm was often assignable to some other type by coincidence, which let a later edit change a reported outcome without the compiler noticing.

The library may not cross a process boundary. When a caller invokes a method on the Supervisor Durable Object, the platform copies the return value to the caller rather than sharing the original object. That copy preserves data and discards behavior. A result value is a class instance whose usefulness lies in its methods, and Cloudflare refuses to copy application-defined classes at all unless they extend the platform's remote-target base class. These do not. So a Supervisor method that returned one would either fail the call outright or hand back a value that has lost the methods its declared type still promises. TypeScript cannot warn about this, because the type is correct on both sides and only the copy in between removes the behavior. Every public Supervisor method therefore keeps returning the plain object it declares today, and the Supervisor converts each internal result into that plain object before returning it.

The same rule applies to anything the system writes down rather than passes along. SQLite rows, R2 objects, module maps handed to the Worker Loader, values placed in a facet's environment, and stored relay and recovery records all outlive the isolate that produced them. Code that reads them later may not share the library or its version, so these records stay plain values with the stable codes the rest of the system already matches on. When a stored record describes a failure, it carries the reason that callers are meant to act on, not the exception message, cause chain, or stack that the error collected inside the isolate.

Workers RPC also decides at the type level whether a returned value can be structured-cloned, and that check rejects any type containing `unknown`. Pi's `AgentMessage` union contains two: a custom message's `details` and an assistant diagnostic's `details`. Every message is plain JSON that clones perfectly at runtime, but a Supervisor method declaring a project thread with Pi messages loses its success arm at the call site, so a caller could ask for a thread and never be able to reach one. The Supervisor therefore hands a thread's conversation across the boundary in the form its SQLite column holds, and exports the parser that turns those bytes back into Pi messages inside the caller's isolate.

The library does offer a serializer that converts a result into a plain envelope, which would survive the copy. We decline it here because adopting that envelope would change the format of every method callers already depend on, and it would buy validation that cf-stumble has no present need for. A later interface may define one deliberately, but it would have to validate both halves of the envelope and prove the encoded values through a real workerd test.

This decision keeps ADR-0003's rule that the Supervisor alone decides activation, ADR-0029's plain startup-check report, and the plain RPC result returned for generation requests.
