# Pure decisions, imperative shells

> **Review:** Agent-only

Every non-trivial decision in the Supervisor is a pure function over plain values, and the effects around it — SQLite reads and writes, `fetch`, Worker Loader mounts, response streams, storage transactions — live in a thin shell that reads the values the decision needs, calls the function, and applies what it returns. A decision takes its facts as arguments and returns a plain result or a discriminated union describing what should happen; it never touches `this.sql`, storage, or the network. That is what makes the branching testable: `decideActivation`, `decidePreparationCheck`, `advanceEpisode`, `selectFallbackGeneration`, `deriveGenerationEligibility`, `decideVerifiedStartupCandidate`, and the recovery episode transforms all run against literal inputs in ordinary tests, with no Durable Object to stand up.

The shells stay small on purpose. A method reads the state it needs, hands it to a decision, and writes the result back inside one storage transaction. The Durable Object is single-threaded and serializes storage, so a read-decide-write sequence cannot interleave with another; that is the only reason a decision may compute `epoch + 1` as a plain value and trust the shell to persist it. In a concurrent store the same code would lose updates and the counter would have to move atomically in SQL.

Classes remain, but not the kind this rule avoids. There is no inheritance hierarchy, no polymorphism, no abstract base, and no method overriding beyond the platform's `fetch`. `Supervisor` and `MainFacet` are classes because Cloudflare dispatches Durable Objects and facets to class instances and offers no functional form; the tagged-error classes come from the better-result library. The remaining service objects — the ones that own a storage handle and expose the operations on it — are a struct paired with its methods, the shape idiomatic Rust writes as `impl`. Rewriting them as factory functions that close over the handle would delete the `class` keyword and change nothing else: the same state, the same call sites, the same encapsulation, moved from a field into a closure. We decline that churn. `MainHarnessArtifact` keeps its private constructor and static `parse` for a stronger reason — it is a smart constructor, so an artifact that has not passed validation is unrepresentable, and a plain record type would give that guarantee up.

Two places keep decision logic inside their shell on purpose. Control's activate and rollback guards parse a label and compare an epoch before delegating to the generation decider; splitting them out would duplicate `decideActivation` for guards already covered through the RPC surface. And the relay-attempt writer keeps its transition inline because the one state a pure transition could forbid — a pre-header failure that carries a response status — is unreachable in the relay flow, and terminal attempts are already immutable by the pending guard; a pure function there would have to invent behavior for a state that never occurs.

This decision carries ADR-0003's rule that the Supervisor alone decides activation, ADR-0033's narrow epoch, and ADR-0035's plain values at every boundary.
