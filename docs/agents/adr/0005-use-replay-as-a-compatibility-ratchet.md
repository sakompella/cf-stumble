# Use replay as an executor-compatibility ratchet

Recorded model responses, replayed against the actual candidate facet rather than a frozen surrogate, validate whether it still produces the tool calls and workspace effects the tape expects at the protocol and version it was recorded against — not whether a changed prompt is better, since the tape came from the old prompt and would otherwise approve a prompt-only change without exercising it. Promotion therefore rejects regressions from the live generation and separately requires supervisor-pinned canaries to pass; prompt-quality evaluation needs fresh, scored trials and remains a different future mechanism. A tape is scoped to the protocol version it was recorded under, so a facet that evolves its tools, prompts, or loop needs a tape recorded against that shape rather than being blocked by one that predates it; the ratchet checks compatibility within a version, not that the version itself never changes.
