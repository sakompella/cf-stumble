# Run every git command in the container's real Git

> **Review:** Human-approved

Every `git` command the agent runs goes to the workspace container and runs the image's real Git at `/usr/bin/git`. The isolate has no Git. This replaces the earlier decision (`c0c929a5`, `617169b2`, and ADR-0026's "host-forwarded Git") that the isolate was the only writer of `.git`: Git ran in the isolate through a CLI layer over Computer's Git library, and the container's `git` was a read-only wrapper that forwarded every write to the Workspace Host.

That layer reimplemented Git's output and rules on top of isomorphic-git, about 4,800 lines with 3,600 lines of tests, and it still did not cover `diff`, `show` or `log --stat`. On 267 recorded scenarios, an agent would have been misled in 23 cases by the layer and in 70 by Computer's Git without the layer; 14 of those 70 left the repository in a different state than Git would, for example an empty commit or a deleted checked-out branch. No wasm Git could replace the layer: none prints Git's command-line output, gitoxide has no push, and a Rust port was estimated at 21 to 27 days. Real Git in the container has none of these differences.

The cost is the container. A Git read takes about 330 ms in a warm container instead of about 80 ms in the isolate, and a Git command on a stopped container starts it (about 6 s) and keeps it running until the ten-minute idle stop (ADR-0043). Production telemetry from 2026-11-04 to 2026-11-11 named no Git command, and about half of all commands already ran in the container, so the extra container time is small. On a provider machine (ADR-0050), Git needs the provider's container, as every other command that is not an isolate program already does.

The router refuses a `bash` call that forces `backend: "isolate"` for a command that runs `git`, with an error that names the container. Other commands the isolate cannot run still go to the container. Git is refused instead, because a caller that forces the isolate for Git expects the isolate's old Git, and the error tells it where Git runs now. The Workspace Host keeps Computer's Git client for its own clones and fetches (the harness provision and a project's clone), which call the client's methods and not its command line. Container Git pushes with the credential helper that `gh auth setup-git` writes when a GitHub credential is installed.
