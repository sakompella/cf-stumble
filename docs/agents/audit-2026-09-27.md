## Architecture and existing safeguards

`src/worker.ts` verifies the Access JWT and owner identity before selecting a tenant Supervisor. The Supervisor owns generation labels, control epochs, stored module maps, project catalog rows, saved Pi threads, and turn leases. Candidate checks run in separate facets; serving and rollback load stored code rather than rebuild it (`src/supervisor/artifacts/index.ts`, `src/supervisor/startup-check/index.ts`, `src/supervisor/generations/index.ts`). The mutable main facet runs the Pi loop and Computer-backed tools; the fixed model route holds model access outside it (`src/facet/generation-0/pi-agent-turn.ts`, `src/model-route.ts`). The Workspace Host owns one Computer workspace per owner, with distinct Git repositories but no security boundary between them (`src/workspace/host.ts`, ADR-0038).

This separation has substance. Access credentials are stripped before facet forwarding (`src/worker.ts`). The Supervisor credits a streamed real turn only after terminal success and a saved thread (`src/supervisor/projects/turn-settle.ts`, ADR-0037). Generation activation uses a transaction and a control epoch (`src/supervisor/generations/index.ts`, ADR-0033). Workspace paths and symlinks receive explicit checks, project commands use process groups and bounded frames, and tests cover lease fencing, stored-artifact rollback, and split UTF-8 frames. `pnpm verify` builds Pi, checks local vendor integrity and protocol, typechecks, formats, lints, builds fixtures, and runs configured Vitest projects (`package.json`). These strengths do not erase the gaps below.

## Priority findings

The order favors faults that can block ordinary work, damage a current clone, or defeat a stated resource guard. Each finding states a code path, its likely consequence, and the smallest useful regression. No fix was made here.

1. **Image results can keep a project thread failing.** The stock read tool emits PNG, JPEG, GIF, or WebP image blocks (`vendor/pi-v0.84.4/packages/agent/src/harness/tools/read.ts:45-57,88-93`). Generation 0 installs it unchanged (`src/facet/generation-0/pi-agent-turn.ts:82-87`), but the text-only route rejects an image tool result before the next model call (`src/facet/generation-0/route-stream.ts:34-47,268-280`). The Supervisor can save model-error state (`src/supervisor/projects/turn-settle.ts:87-116`), so a later text-only turn can meet that image again. This is a deterministic contract mismatch, not a measured production failure. Test a real PNG read, save and reload the thread, then send a text follow-up. Either return an explicit text-only unsupported-image result or support image transport end to end.

2. **Project connection and removal lack one ownership fence.** Disconnect removes the catalog row before awaiting workspace deletion, so a reconnect can provision the same project ID while the old deletion is pending (`src/supervisor/projects/project-connections.ts:331-355,451-457`). Removal targets the fixed clone path and also removes `.provision-lock` (`src/workspace/project-removal.ts:55-62`). Separately, a failed first connection unconditionally deletes its row after an overlapping second connection may have succeeded (`src/supervisor/projects/project-connections.ts:451-462`, `src/supervisor/projects/connected-projects.ts:207-209`). Supervisor interleavings are supported by the control flow; the exact filesystem outcome under Computer is untested. A later turn may reprovision a missing clone, but that cannot restore uncommitted work. Serialize same-ID lifecycle operations or use durable ownership/version checks. Test deferred removal followed by reconnect, and two overlapping connects where the first fails after the second succeeds.

3. **OAuth-only private projects bypass the repository-size ceiling.** The GitHub API size lookup receives only the optional `GH_TOKEN` fallback, before the workspace's interactive credential is checked (`src/supervisor/projects/project-connections.ts:179-186,276-319`). A private-repository 404 becomes unknown and is admitted (`src/github/repository-size.ts:43-56`, `src/supervisor/projects/project-connections.ts:91-113`). Neither the later clone nor turn-time reprovision enforces the 3,000-blob and 150 MB blob-byte limits (`src/project-provision.ts:159-177`, `src/supervisor/projects/project-connections.ts:397-442`). Fail-open for transient API failures is a policy choice; the OAuth-only private case systematically misses the preflight. Measure with the workspace credential or apply a bounded authorized fallback, without logging the token. Test a private API 404, valid workspace access, and an oversized tree; test reprovision after growth or reset. No oversized private clone was run.

4. **Free-text exception logs do not redact JWTs.** `causeText` applies GitHub credential redaction then truncates to 400 characters (`src/diagnostics.ts:48-52`), while JWT redaction applies only to structured fields (`src/diagnostics.ts:84,109`). The JWKS test asserts absence of the complete synthetic token, which truncation alone can satisfy (`test/access-jwks.test.ts:108-131`). A JWT-bearing exception can expose header or claims text, or a whole short token. The normal JWKS fetch does not send the Access token, so no actual production leak is shown. Redact before truncation and assert absence of distinct segments in short and long synthetic tokens. Apply the same exception sanitizer to artifact builder catches that currently log `String(error)` (`src/supervisor/artifacts/builder.ts:73-80,112-117`).

5. **Harness provision lock ownership is published too late.** The shell creates its lock directory before writing the PID. A contender treats the empty PID as a stale lock, removes it, and can enter; the first holder's unconditional exit trap can then remove the successor's lock (`src/harness-build-provision.ts:17-29`). Different-commit builds can contend because the builder's provision step is not inside workspace provisioning exclusion (`src/supervisor/artifacts/build-workspace.ts:141-192`). Test two real shell processes paused between directory creation and PID publication, then test takeover after a dead owner. Publish ownership atomically without losing crash recovery. Actual incidence has not been measured.

6. **A second compaction loses Pi's prior-summary semantics.** The adapter represents every saved item, including `compactionSummary`, as a normal message (`src/facet/generation-0/compaction.ts:29-37,76-87`). Pi selects its iterative update-summary prompt only when it finds a `compaction` entry (`vendor/pi-v0.84.4/packages/agent/src/harness/compaction/compaction.ts:545-554,624-646`). The prior summary text may still appear as conversation text, so total context loss is not established. Test two compactions and inspect the second prompt for the structured previous summary; also test a retention setting with no useful cut point. Preserve old saved-thread readability when changing the adapter.

7. **The normal test gate omits lint-rule fixtures.** Vitest includes `test/**` and `src/**`, but not `tools/**` (`vitest.config.ts:16-17,24`), while `pnpm verify` invokes that configured test command (`package.json`). Twenty-four `tools/oxlint/anti-slop/**/*.test.ts` files are therefore not executed by this gate. Enabled rules still lint project code, and five fixture files target an intentionally disabled Effect plugin; this is a fixture-coverage gap, not proof of a broken rule. Establish a suitable Node runner for RuleTester and the standalone CLI assertion test, then prove an intentionally broken fixture fails `pnpm verify`.

## Smaller follow-ups and conditional questions

The next local changes can be independent. An older GitHub device redemption can clear a replacement pending code (`src/supervisor/projects/github-connection.ts:211-250`, `github-connection-store.ts:75-97`). Both flows belong to the same owner; the likely visible loss is the newer user code, not cross-owner credential installation. Late HTTP refusals and fresh-thread errors can write status into a newly selected project's page (`src/page/script-turn.ts:192-208`, `src/page/script-conversation.ts:120-137`); guard after awaits and test project switches in the browser harness. The turn-stream ceiling counts decoded code units instead of UTF-8 bytes (`src/supervisor/projects/turn-stream.ts:90,117-118,146-154`). Command decoders lack an EOF flush (`src/workspace/project/exec-operation.ts:211-238`), and directory listing RPC returns every entry (`src/workspace/project/target.ts:435-448`). Add boundary tests before changing those contracts.

Other follow-ups concern repeatable checks. The Computer tarball verifier reads an ignored checksum file (`scripts/vendor/verify-computer-tarball.sh:12`), and container preflight treats Wrangler's Dockerfile path as a pullable image (`scripts/probe/container-preflight.sh:56-58`, `wrangler.jsonc`). The final Docker runtime stage and package feeds are mutable (`containers/computerd.Dockerfile:108-122`). Browser launch and CDP attach failures lack cleanup (`tools/browser-harness/chrome-launch.mts:67-77`, `browser.mts:32-36`). These are reproducibility or cleanup gaps, not evidence that today's deployed image is bad. Terminal turn status lacks a concise live-region announcement (`src/page/markup-conversation.ts:24,33`); check with a real screen reader before claiming user-observed impact.

The following need an external or concurrent-runtime test before they become incident claims. Overlapping same-commit startup checks may abort one another (`src/supervisor/startup-check/candidate.ts:123-126`); hold one response in a workerd test. A provider JSON error followed by `[DONE]` can be ignored by the SSE parser, but the pinned provider's actual error format is unknown (`src/model-route-stream.ts:94-120,289-299`). Missing provider usage undercounts tool schemas in the fallback estimate, and malformed usage numbers pass parsing (`src/model-route-stream.ts:244-259`, `src/model-route-stream-parse.ts:64-94`); check real response shapes while adding local tests. Producer cancellation after a browser disconnect and isolate-local workspace exclusion across eviction need platform lifecycle tests (`src/model-route-stream.ts:271-300`, `src/workspace/provisioning.ts:341-343`). Workspace reset during a turn needs an explicit owner policy, either refusal or cancellation and fencing (`src/supervisor/supervisor.ts:219-231`).

## Decisions and verification boundary

Do not recast deliberate choices as bugs. ADR-0030 omits a generation-request journal. ADR-0038 permits sibling-repository access in one owner's workspace. ADR-0039 permits unrestricted internet and local GitHub credentials. ADR-0040 excludes untracked-only files from the turn diff. ADR-0042 keeps ignored dependency trees container-local. The browser harness is deliberately outside the normal gate. Vendor hash checks establish consistency with the local manifest, not independent upstream Pi provenance; a separate pinned-upstream comparison would improve release review.

A repeated passing startup check inserts another preparation-check history row and advances the control epoch (`src/supervisor/generations/index.ts:120-130`, `test/supervisor/epoch-scope.test.ts:88-126`). Its `effect: "no-op"` names the unchanged generation status, not an unchanged transaction (`src/supervisor/generations/decisions.ts:91-109`). ADR-0033 requires epoch changes for preparation checks, and the current status note agrees. Suppressing this epoch advance is not an audit fix; changing the rule would require revisiting the ADR.

This draft is a map for targeted tests, not a certification of deployed behavior. Run `pnpm verify` before claiming a subsequent fix works. Run `pnpm harness:browser` for page changes and use a paid or live environment only where the claim depends on Computer, service binding, Access, or GitHub behavior. No production incident, credential leak, clone loss, browser behavior, or provider failure was observed in this audit.
